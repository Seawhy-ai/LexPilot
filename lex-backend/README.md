# SeaWhy Lex 独立账号与 AI 服务

本目录在 Node.js 24 运行，账号保存在独立 SQLite 数据库，不使用律衡师生表。AI 服务读取现有服务器配置中的 DEEPSEEK_API_KEY，密钥不会发往浏览器。

账号使用 scrypt 密码哈希和独立随机盐；会话随机令牌只以哈希存储，浏览器使用 Secure、HttpOnly、SameSite=Strict Cookie。AI 仅允许有效会话调用，限制输入大小；AI 返回允许 SSE 流式响应。所有写请求检查 Origin。

个人档案（昵称、头像、积分、等级依据及装扮）保存在独立账号数据库，旧设备档案仅经用户确认后导入。其他学习记录、笔记等仍在浏览器本地，不随账号同步，也没有实现同一设备上不同账号之间的本机数据隔离。旧浏览器本地账号不会自动迁入新数据库，需重新注册。积分由客户端更新，不是可信的支付、兑换或权益结算依据。个人档案采用版本校验：跨设备冲突时保留本地未同步副本，不自动覆盖云端。

## 生产部署前

1. 核验原律衡服务和数据库的状态；无需改写或迁移它们。
2. 使用独立路径 `/opt/seawhy-lex` 与 `/var/lib/seawhy-lex/users.sqlite`。不在公网目录放后台代码或配置文件。先检查目录是否已有用户数据并备份。
3. 服务以 `lvheng` 非 root 用户运行；创建独立数据目录并授予该用户所有权。`seawhy-lex.service` 通过 Node 的 `--env-file=/etc/lvheng/backend.env` 共用 DeepSeek 密钥，不修改该文件。前提是对应账户有读取权限。
4. HTTPS Nginx 中将 `/api/lex/` 代理到 `127.0.0.1:3100`；API 不走静态文件，禁止公开监听 3100。为登录与注册配置独立 IP 限速，为 AI 接口配置请求速率和并发上限；公网开放注册仍有滥用风险，需要预算告警和进一步的账号级配额。
5. 先独立测试注册、重复账号、错误密码、登出、未登录请求、登录态的模型正常和失败返回、SSE、跨站请求拒绝及限流，再切换页面文件。
6. 更新静态目录的 `law.html`、`law-app.js`、`lex-auth.js`、`sw.js`；保留旧文件备份。不要把仓库 `.git`、后台代码、环境变量或密钥拷入网站目录。
7. SQLite 正式数据做好在线备份（sqlite3 `.backup`），并核验恢复。证书和防火墙应继续保持现有 HTTPS 配置。预留回滚方式。

执行 `node --test lex-backend/test.mjs` 和 `node lex-backend/ui-test.cjs`（UI 测试需本地 8767 静态服务、Playwright、Chromium）。这些测试使用模拟响应，不能证明生产环境模型调用成功。
